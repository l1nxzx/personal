# Development

Requires Node 20+ (Netlify and Render pin 20; the author's machine runs a newer Node). Windows with Git Bash/PowerShell is the author's environment; commands below are shell-neutral.

## Setup

```
npm run install:all
```

1. Firebase console: create a project, enable Firestore and Cloud Storage, generate a service account key.
2. Save the key as `server/serviceAccountKey.json` (gitignored).
3. Copy `server/.env.example` to `server/.env` and set `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` (each ≥32 chars; the example shows the generation command) and `FIREBASE_STORAGE_BUCKET`.
4. `npm run create-super-admin -- --email you@example.com --name "Name"` (prompts for the password; also promotes an existing email).
5. `npm run dev`, open http://localhost:5173.

## Commands

All from the repo root; each delegates to `server/` or `client/`.

| Command                      | Does                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------ |
| `npm run dev`                | Server (`tsx watch`) and client (Vite) together                                |
| `npm run build`              | `server`: `tsc -p tsconfig.build.json`; `client`: `tsc --noEmit && vite build` |
| `npm test`                   | Server vitest only                                                             |
| `npm run lint` / `typecheck` | Both apps                                                                      |
| `npm run format`             | Prettier over client, server, shared, root json/yaml/md                        |

Single server test file: `npm --prefix server test -- test/tasks.test.ts` (verified; `npm exec vitest` from the root does not load the test config and fails).

## Environment variables (`server/src/config/env.ts`)

`NODE_ENV`, `PORT` (4000), `CLIENT_ORIGIN` (comma list allowed; must match the site exactly for cookies/CORS), `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `ACCESS_TOKEN_TTL_SECONDS` (600), `REFRESH_TOKEN_TTL_SECONDS` (14 days), `COOKIE_SAMESITE` (`lax`), `ALLOW_REGISTRATION` (`false`), `FIREBASE_SERVICE_ACCOUNT_PATH` (`./serviceAccountKey.json`), `FIREBASE_STORAGE_BUCKET`, `REDIS_URL` (optional; required for >1 instance), `LOG_LEVEL`. Client: optional `VITE_API_URL` (default `https://personal-2-phi0.onrender.com/api`; set `/api` for the local Vite proxy).

Secrets (JWT secrets, service account key) live only in `server/.env`, the key file, and the Render dashboard. Never paste values into docs or commits.

## Local development vs production

- **Local:** the server reads the service account key from disk and talks to your real Firebase project (there is no emulator setup in the repo), so local runs read and write real data. Registration is closed unless `ALLOW_REGISTRATION=true`.
- **Production:** Render injects env vars; the key is mounted as a Secret File at `/etc/secrets/serviceAccountKey.json`; `JWT_*` secrets are generated by Render (`render.yaml`); Netlify rewrites `/api/*` to Render.
- **Tests:** never touch Firebase; data is replaced by in-memory fakes.

## Testing and QA

- Server tests: `server/test/*.test.ts`. When changing a `data/*Repo.ts`, update the fakes in `server/test/memory.ts` / `memory3.ts`.
- Fakes cannot reveal real Firestore problems (indexes, transaction limits, query semantics).
- UI QA approach used so far: run the API with the data layer redirected to the in-memory fakes and the Vite app on spare ports (e.g. 4100/5273) so the owner's own 4000/5173 servers and real data are untouched, then drive it with a headless browser at ~390px and ~1440px. That tooling lives outside the repo.
- Login and the general API are rate limited; automated browser runs should sign in once and reuse the session.

## Deploy

- **Render** (`render.yaml`): root dir `server`, build `npm ci && npm run build`, start `npm start`, health check `/api/health`.
- **Netlify** (`netlify.toml`): base `client`, build `npm run build`, publish `dist`, Node 20, SPA fallback, `/api/*` proxy. The Render host in `netlify.toml` is hardcoded.
- SSE through Netlify's proxy may drop long-lived connections; fallback is `VITE_API_URL` pointing at Render with `COOKIE_SAMESITE=none` (see README).
